Challenge 7: Every Partner's Vault

Content access filtering and IP protection

Open the PoC
Product outcome Every studio trusts that only it can see its own games, data and math models, and can prove it.

Why now

Business brief

  • 2 studios raised concerns after seeing competitor names in a shared report.
  • IP protection is a top 3 reason studios choose an aggregator.
  • A new top studio will only sign with an access audit.

Tech brief

  • Permissions are set manually per account, using broad roles (admin, studio, operator).
  • Shared reporting is only partly filtered by studio.
  • Audit log: 3 pts. Role-based access rebuild: 8 pts.
  • Any access change needs a security review.
  • Capacity: 16 pts.

Outcomes and goals

Sequence

1. ContainHotfix shared reports (no review). Lock down the staff math-file tool now, via an emergency security sign-off.
2. Prove (no review)Exportable audit log, built to also record permission changes and staff access. Use it to look back at who opened math files.
3. Isolate (security review)Studio-scoped RBAC in one batched submission, including a staff support role with no standing math-file access. Start the review early so it overlaps the build.
4. HardenCross-tenant and staff-access tests, plus review findings, from the reserve.

Curveball: staff tool opens every studio's math files

A security check found an internal support tool that lets staff open every studio's math files. We close it inside the existing outcomes instead of adding a new workstream.

Studio communication: decide who is told and when once the look-back shows whether anyone accessed the files. Check contracts and regulatory obligations, as math models are usually certified assets.

Curveball 2: operator wants cross-studio benchmarks, studios object

Approach: ask the operator what they actually want to decide, then deliver it at the aggregation level. We aggregate performance by game type, theme and similar groupings across all studios, and never expose an individual studio.

  • Ask first: the operator's real decisions are often narrower than "cross-studio benchmarks".
  • Aggregate only: benchmarks by game type, theme and similar groupings, with no studio or title names.
  • No IP: math models and raw player data stay out of scope.
  • Studios hear it first: present the aggregate design to the objecting studios before the operator sees terms.

Fit with the plan: it is a new access path, so it needs the security review, and all 16 pts are allocated. Position it as a follow-on once the four outcomes are done.
